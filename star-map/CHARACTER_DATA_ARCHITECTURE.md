# キャラクターデータ構成

## 方針

プロフィールサイトのキャラクターデータ元を次の2サービスへ移行する。

- いあきゃら: CoC6 / CoC7
- キャラッシュ: エモクロアのみ

Chara Libraのブラウザ保存領域は移行完了後にデータ元から外す。

## データフロー

1. 各サービスのキャラクター一覧画面から、個別ページを開かずに台帳を生成する。
2. 台帳上で公開サイトへ取り込むキャラクターを1件ずつ選択する。
3. 選択したキャラクターだけ個別ページから詳細情報を取得する。
4. 共通形式へ正規化し、公開用の `data/characters.json` を生成する。
5. 公開用JSONだけをGitHub Pagesへ配置する。

一覧台帳には非公開キャラクターが含まれる可能性があるため、
`data/private/` 以下へ保存し、Git管理およびGitHub Pages公開の対象外とする。

## 一覧画面から取得できる項目

| 項目 | いあきゃら | キャラッシュ |
|---|---|---|
| ソース内ID | ○ | ○ |
| システム | 6版 / 7版 | エモクロア |
| 名前 | ○ | ○ |
| ふりがな | ○ | ○（未設定あり） |
| 職業 | ○ | ○ |
| 更新表示 | 保存日時 | 更新日時または移行表示 |
| タグ | ○ | 一覧カードでは取得不可 |
| 現在正気度 | ○ | 対象外 |
| ロスト状態 | 一覧フィルターから判定 | エモクロア絞り込みでは0件 |
| 画像URL | ○ | ○ |
| 閲覧URL | ○ | ○ |
| 編集URL | ○ | ○ |

## 台帳レコード

各 `entries` 要素は次の共通項目を持つ。

- `source`: `iachara` または `charash`
- `sourceId`: サービス内のキャラクターID
- `system`: `CoC6`、`CoC7`、`エモクロア`
- `name`: 一覧表示名
- `reading`: 一覧表示のふりがな
- `occupation`: 一覧表示の職業
- `updatedLabel`: 一覧上の更新・保存表示
- `tags`: 一覧から取得できたタグ配列
- `isLost`: 一覧から判定できたロスト状態
- `imageUrl`: 一覧画像のURL
- `detailUrl`: 閲覧ページURL
- `editUrl`: 編集ページURL
- `importStatus`: 初期値 `pending`

いあきゃらのレコードには `currentSan`、キャラッシュのレコードには
`createdUpdatedLabel` も保存する。
